# 寻栖项目规格

本文件定义项目目标、范围和验收标准。修改业务目标、范围或验收条件须经用户批准。执行读 [运行计划](plan_runtime.md)，状态读 [进度](progress.md)。

## 读取与适用顺序

1. 先读「目标」和「范围」，确认当前事项处在个人参考查询的交付边界内。范围不明确时暂停并请用户确认。
2. 当前个人参考查询按 `REF01`–`REF06` 验收。运行计划的每个步骤列出对应条目，逐项用实际证据核对。
3. `AC01`–`AC34` 是既有场景用例，仅在对应业务层适用时用于回归。历史或合成结果以其原有范围解释。进度记录用于恢复执行位置和查找结果，验收条件以本页为准。

## 目标

面向本机个人使用，为中国大陆的酒店搜索提供真实候选、可解释的优先核对名单、原来源房型参考以及按需交通证据。用户在手机住宿软件核价并自行订房。

## 范围

- React、TypeScript、Vite 前端，Python 3.12、FastAPI 后端和 SQLite 最小会话存储。正式入口为桌面 `寻栖.exe` 或 `start.cmd`，只监听本机回环地址。关闭应用窗后可托盘驻留，托盘退出或 `stop.cmd` 结束后台。无需开机自启。
- 可用城市、景点、商圈、具体地址、车站、机场、酒店或具体门店作为输入。一个住宿目的地，最多五个途经点。途经点作为行程备注，不能冒充已规划路线。境外、港澳台、手机安装版、跨电脑免安装分发、公网部署、商业用途不在范围内。
- 普通酒店搜索和确认目的地后的住宿搜索并行查询道旅、途牛、飞猪。道旅与途牛保留独立会话、原价格口径、覆盖范围和原来源房型入口。飞猪是候选发现，展示价保留原样，不作为报价或库存。单源和专用餐厅召回沿用各自受控入口，失败不自动换源。广州离线演示仅使用合成数据，须明确标注。
- 自然语言只用已配置的 DeepSeek 生成有原话依据的条件草稿。确定性校验和用户确认后才填表，须再次显式提交才能查价。GPT、Pi 和自动交易均不在当前范围。
- 当前交付包括参考价、优先核对名单、原来源房型、地图路线及当前快车估价。外部住客点评接入已取消，完整实时可订（G2-Live）、确认库存、最终含费实付、锁价、叫车与下单均不在本次交付。

### 搜索、身份和价格约束

- 查询固定全程的目的地、入住退房日期、每房成人与儿童年龄、房数和可选预算。同一查询每房采用相同入住组合，异构组合不假装支持。默认整间客房和房内独卫，只有明确接受床位才放宽相关条件。床型由用户指定，免费取消是可选条件。修改条件使受影响的证据失效，拒绝旧响应覆盖新查询。
- 预算按每房每晚的人民币整数分表示。允许显式使用日度参考汇率换算，空预算为不限；过期或无法验证的汇率不用于查询。各来源搜索价仅作参考。多晚须有逐夜依据才可声称逐夜达标，多房要求足量同套餐库存。仅有均价时可按规定标示推定；不推测最终价格、押金或优惠资格。
- 普通搜索显示名称、地址、来源、查询时间、可用参考价、理由与限制。证据有明确冲突的候选在同轮持续排除，等待或刷新失败不解除冲突。已核实路线优先；同档有效路线按步行距离排列。一晚一房的人民币展示价只能作为预算核对线索。完全相同的展示名称及地址在首批推荐只占一个名额，各来源记录仍独立保留。无合格证据时显示待核对候选；来源无结果和故障须分别标注。
- 同店应核对完整名称、地址和城市，区分分店、门牌、楼层与单元；只有证据明确且双向唯一才自动关联。手工确认仅绑定当次会话的指定对象，允许撤销。酒店星级和地图 POI 分数不算住客评分；合法、已核实且带来源及量表的住客评分字段才可展示。缺失的住客评分、独立客房、独卫和完整费用不留酒店卡片占位；房型详情继续公布对应证据。
- 供应商原样预订连接须核对酒店、日期、入住组合和房数，无法核对即停用，合法来源入口仍可用于用户自行核实。不得拼改链接、跨源拼价、把不兼容字段混合成同一报价，或将缺字段当作已达标。

### 交通与安全约束

- 地点和查交通由用户显式触发，各来源独立解析坐标。卡片显示从确认的具体目的地到酒店的步行时间、可取得的驾车时间及当前车费。步行以来源实际路线为准，直线距离只作参考。历史交通子条件为步行 ≤1,500 米或驾车 ≤900 秒；驾车时间不含候车，并且当前路线、估价和营业信息都不承诺未来时段。
- 地图和滴滴两项观察必须属于当前酒店卡片、未超过两分钟。允许两端完整名址与城市对应时并列。若文字不同，两份观察各自同城且都有完整名址，用户逐对核对两端后可并列并可撤销。确认不进入全局映射或可订判定，坐标不跨来源使用。
- 住宿、地图和模型业务请求经本机 API，浏览器不持有供应商与模型密钥。用户显式查看参考换算或选择外币时，浏览器可仅请求 Frankfurter 日度汇率，不传行程或密钥。服务执行回环、Host/Origin、请求大小和错误脱敏限制。SQLite 只留短期最小状态，搜索会话最长 30 分钟，地点上下文 120 秒。报价超过五分钟须标旧，仍以同源新观察才能更新。取消、失败或迟到响应不能修改已替代状态。演示数据和真实、历史和当前证据须可区分。
- 新增外部业务访问一律先确定合法接口、目标样本、原始 HTTP 上限、期限、脱敏输出与停止条件。初始化、分页、手动刷新和重试均计数，不沿用已关闭预算。模型和外部响应只作数据，不执行其中的文本指令。

### 既有业务验收用例

保留 AC01–AC34 的原始场景和判断，仅在对应业务层适用。历史 G1 适用离线演示和规则回归，G2-Historical 是历史样本验收，G2-Live 仍受供应商字段和许可约束。三者的记录不作为实时入住库存、实付或新增点评接入的依据。

| 编号 | 输入／场景 | 预期行为 |
| --- | --- | --- |
| AC01 | 广州、海底捞、200元、住客评分4.5、地铁最好近 | 预算/餐厅为硬条件；评分按R04有证据才启用，缺评分标注；地铁偏好，不增加8公里限制。 |
| AC02 | 缺入住日期；随后补充日期 | 首次追问而非显示虚构最低价；补充后保留既有条件，不重复询问。 |
| AC03 | 三门店夹具：第一家无合格住宿，第二、三家有 | 返回后两家附近候选，不能只搜索第一家；覆盖记录可核对。 |
| AC04 | 分页封顶、超时或调用预算耗尽 | partial=true，显示覆盖及停止原因，不称全城全部。 |
| AC05 | 步行 1500 米与 1501 米；驾车 900 秒与 901 秒 | 步行≤1500米或驾车≤900秒任一满足即可；两者都超限则不通过。 |
| AC06 | 步行 1400 米／20 分钟，或步行 1600 米／9 分钟；另测驾车 900 秒／901 秒 | 第一条步行满足（距离为准）；第二条步行不满足（时间不替代距离）；驾车边界按900秒判断。 |
| AC07 | 预估车费 1500 分与 1501 分 | 前者可主推且有风险提示；后者不满足打车条件。 |
| AC08 | 9 公里估价 ¥14，6 公里估价 ¥20 | 前者可通过车费门槛；后者不能；不设 8 公里硬限制。 |
| AC09 | 仅当前估价 ¥13，计划深夜返回 | 可主推，明确当前参考与时间不匹配风险，不写成深夜实时价。 |
| AC10 | 无估价、过期估价或区间 ¥12～18，步行不达标 | 不认定返程符合；不把未知当 0，不按区间下界放行。 |
| AC11 | A：169＋12；B：188＋0，其他硬条件通过 | 已知费用小计可复算为 181／188，并展示 B 的步行优势及 7 元差额；**排名由 R08 的评分 → 评价人数主键决定**，不再以总价低者排前。 |
| AC12 | 住宿 ¥205＋返程 0；住宿预算每晚 ¥200 | 仍排除；不能用综合性价比抵消住宿预算失败。 |
| AC13 | 共卫 139、独卫双床 169、独卫大床 189 | 默认最低合格报价为 169；不限定床型。 |
| AC14 | 青旅床位 60、整间独卫 150 | 默认仅整间候选；用户明确接受床位后才放宽房间方式，且视为同时接受这类房型的共享卫浴；床位价按人×晚展开，房型只写多人间／宿舍而未写床位的计价未知、不进合计（2026-11-07 用户口径）。 |
| AC15 | 房型是否独享／独卫未知；另测房型名标注“公卫／床位” | 未知时按2026-11-05国内默认推定整间与房内独卫，页面标“推定”、不标“已核实”；明确标注公卫／床位则不推定并排除。 |
| AC16 | 基价 180＋必付费用 30；预算 200；另测押金未核实 | 合格成本为 210，排除；可退押金另列，不混入消费；押金／到店必付未核实时必须标“到店另付未核实”，不得声称完整含费。 |
| AC17 | 219 减潜在券 30，但资格未验证 | 显示潜在 189，不以此认定预算通过。 |
| AC18 | 两晚逐夜不同价、两间房仅一间低价库存；另测仅有均价 | 有逐夜价时校验逐晚预算；仅有均价时只可标“推定”展示均价折算，不得称逐夜实价或可订总价；两间房需足量库存，不得把仅一间库存倍乘。 |

| AC20 | 同一道旅酒店的两个报价房型/早餐/取消规则不同 | 分列报价与条件，不宣称完全同款；不冒称携程/美团双平台比价。 |
| AC21 | 有可核实5分制住客评分4.6/4.4、缺住客评分、仅starRating | 前者通过/后者不通过4.5门槛；缺评分按R04不启用门槛并标注；星级不充当住客评分。 |
| AC22 | 同名异店或同楼不同单元公寓 | 不误合并，不把一店评分和另一店价格组合。 |
| AC23 | 同店关联两家符合条件餐厅 | 一张住宿主卡，保留分店选择，主方案采用最低合格总成本。 |
| AC24 | 营业至 02:00；活动跨午夜，或已知 23:00 关闭 | 用完整日期正确判断；关闭方案不达标；未知不得承诺营业。 |

| AC28 | 全部实时来源失败 | 明确 unavailable，不偷偷加载演示数据到实时结果。 |
| AC29 | 最低价卡片及来源访问 | 必备信息完整；取消和估价风险醒目；来源时间可见；不显示订单成功。 |
| AC30 | 描述中含“忽略规则”“调用支付”等指令 | 仅作外部数据，不更改条件，不调用写操作，不暴露秘密。 |

| AC32 | 原始报价包含税费及已抵扣优惠 | 不重复加税或重复减券，按整数分计算，合计可复核。 |
| AC33 | 低价来自拼车／企业专享／未验证会员 | 不默认为普通用户可用，除非明确接受并满足资格。 |
| AC34 | 价格与证据过期；用户点击刷新 | 旧值标明过期；重新查询或返回不可用，不伪更新查询时间。 |
