# 寻栖运行计划

本页给出唯一的执行顺序。验收条件来自 [规格](spec.md)，执行位置来自 [进度](progress.md)。

## 逐步执行流程

1. 按 [仓库执行规则](../AGENTS.md) 读规格、本计划和进度。以本页步骤表从上到下的顺序为执行路线，逐行从 `S1.1` 走到最后一行。
2. 读取 `current_step`。只定位这一步。它必须紧接 `last_accepted_step`，且所在阶段须等于 `current_stage`。首次执行时 `last_accepted_step` 为 `null`，只可执行首步。两者都与进度一致后，将这一项由 `ready` 改为 `doing`。恢复已有 `doing` 时继续同一步。
3. 只实施当前行的「执行动作」。再核对该行 `done_when` 和「规格条目」，用适合的测试、实际观察或用户核对取得证据。动作做完、测试通过与规格验收是三件事，实际证据须逐项满足当前验收条件。
4. 验收通过后，在进度里记下步骤 ID、验证方法与结果，再将 `last_accepted_step` 更新为该步。下一行成为唯一 `current_step`，状态先置为 `ready`。当前阶段的最后一步还须复核本阶段各步均已通过，才可标记该阶段 `done` 并进入下一阶段。更新进度后运行 `scripts/check_docs.py`，检查通过才可执行下一步。
5. 验收失败或证据不足时，保留当前步骤，记录原因并在该步修正。缺授权、关键数据或需用户裁决时，标为 `blocked`，等待解除。文档有冲突、步骤指针不一致或找不到对应规格条目时暂停，请用户裁决。
6. 验收完成最后一步才可将 `current_stage` 与 `current_step` 同时置为 `null`，状态记为 `done`。此时当前计划结项。新增任务须先经用户明确并纳入计划，已有验收记录供所对应的步骤复核。

任一时刻只允许一个 `doing`。可按需细化尚未执行的步骤，但仍须保留已验收步骤的编号和证据，逐行串行，满足同一份规格。历史结果的编号映射见 [进度](progress.md)。
